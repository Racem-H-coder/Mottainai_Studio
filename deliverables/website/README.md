# Tameru website pack

Everything needed to build the Tameru project website: text, numbers, chart data and figures.

> **Rule for the site:** quote numbers from `site_data.json` only. Every number is **simulated** (a synthetic
> farm district on real weather data) and must be shown with a "simulated" label. Items with
> `"assumption": true` (fault rates, fault and anomaly results, the proposed tariff) must also say they rest on
> assumed values. Items with `"simulated": false` (STEG tariffs, 2026 shedding windows, grid emission factor) are
> real reference values: show their `source`. Peak numbers carry a `basis` (mean of the 20 days or worst day):
> compare mean with mean and worst day with worst day.

## Files

| File | What it is |
|---|---|
| `PROJECT_REPORT.md` | The full project story in plain language. Covers the problem, the idea, how it works, architecture and IoT contract, the AI, the data, results, demo story, limitations, roadmap, glossary, and a 10-question FAQ. Source for any long-form page. |
| `copy.md` | Short website text: hero, 3 feature cards, 5-step "how it works", results section, call to action. Numbers are tagged with their `site_data.json` id. |
| `site_data.json` | Every headline number as `{id, label, value, unit, explanation, simulated: true}`, some with `assumption: true`. The single source of truth for figures on the site. |
| `charts/*.json` | One file per chart, ready for Chart.js 4 (see below). |
| `figures/*.png`, `figures/*.svg` | Static versions of the report figures, if you prefer images to live charts. |

### Charts

| File | Shows |
|---|---|
| `worst_day.json` | Feeder load on the hardest day: no Tameru / open loop / closed loop, plus the 1,000 kW capacity line |
| `adoption_sweep.json` | Mean and worst peak (lines) and hours over capacity (bars, right axis) vs share of farms equipped |
| `scenarios.json` | Mean and worst peak per scenario at 50 % adoption; also has a `table` field with the full numbers |
| `forecast_day_normal.json`, `forecast_day_heatwave.json`, `forecast_day_holiday.json` | Forecast vs actual for three example days; the p50–p90 band is drawn with `fill: "-1"` |
| `error_by_hour.json` | Forecast error by hour: Tameru vs two simple baselines |
| `feature_importance.json` | What the forecaster relies on (horizontal bars) |
| `forecaster_v1_v2.json` | Forecast band coverage by hour: before calibration, the v2 experiment, the model in use |
| `margins.json` | Effect of an extra planning margin at 70 % and 80 % adoption (almost none) |
| `faults.json` | Unmet irrigation water without and with faults (assumed rates), no Tameru vs Tameru; also a `table` field |
| `water_budget.json` | Pumping vs FAO-56 crop need and the 110 % budget, budget off vs enforced; also a `table` field and `factor_source` |
| `anomalies.json` | Anomaly detection precision and recall (observable faults) per fault type; also a `table` field |

Each chart file is a Chart.js config with extra fields: `title`, `caption`, `simulated: true`, and sometimes
`table` or `assumption`. Chart.js ignores unknown top-level keys, so you can pass the file straight in:

```js
const cfg = await (await fetch("charts/worst_day.json")).json();
new Chart(document.getElementById("worst-day"), cfg);   // show cfg.caption under the chart
```

Colors follow the report palette. Change `borderColor` / `backgroundColor` to match the site theme.
`options.plugins.subtitle` already carries the "Simulated" note.

## About the 3D demo

`index.html` (the 3D digital twin with the guided demo) runs **its own simplified, illustrative simulation** in
the browser. Its on-screen numbers are for telling the story and are not the backtest results; the demo now carries the label "Illustrative simulation: numbers differ from the backtest; see the project report". On the website,
quote results from `site_data.json` only, never from the 3D demo.

## Regenerating

The JSON files and figures are generated by `tameru_data/export_site.py` from the backtest results. If the
models or the backtest are re-run, run `python export_site.py` again and the numbers here update. The text
files (`PROJECT_REPORT.md`, `copy.md`) are written by hand and must then be checked against `site_data.json`.
